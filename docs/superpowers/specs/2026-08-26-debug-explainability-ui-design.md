# Matera Pixel Probe Explainability UI Spec

## Purpose

Upgrade the current pixel probe report into an offline debug workbench that explains every extraction and routing decision with numbers, images, and a readable decision story. The target user is a developer/operator improving OMR accuracy and reducing `needs_review`, who needs to ask questions such as:

- Why is `Q6/f` `BLANK`?
- Did global topology run for `Q6`, and why did it not select `f`?
- Which pixels were removed as printed text, outside radius, HSV noise, or contour outliers?
- At which stage did the pipeline commit to `MARKED`, `BLANK`, or `AMBIGUOUS`?

This is a debug/reporting enhancement only. Do not change production scoring behavior unless a later task explicitly asks for algorithm changes.

## Design Principle

The report should answer "why" without requiring source-code reading.

Every final decision must be backed by:

- a stage-by-stage explanation
- thresholds and measured values
- visual artifacts for the pixels used or discarded
- routing context at question level
- global topology context when applicable

Use a dense dashboard style: compact, scan-friendly, high contrast, table-heavy, and work-focused. Avoid decorative layouts. The report must work from `file://` with no server and no external CDN.

## Required UI Layout

### 1. Top Summary Bar

At the top of `index.html`, show a dense summary strip:

- source PDF
- page number
- alignment score
- number of questions
- number of ROIs
- count of `MARKED`
- count of `BLANK`
- count of `AMBIGUOUS`
- count of `needs_review`
- count of suspicious traces
- links to `page_trace.json`, `roi_trace.csv`, `page_summary.md`, `raw_page.png`, `aligned_page.png`, `reference_page.png`

Use badges with fixed width where possible so values do not shift layout.

### 2. Question Navigator

Add a left-side question navigator or top compact navigator when screen width is small.

Each question row should show:

- question id
- selected/marked option badges
- `needs_review` badge when any option needs review
- method mix badges, for example `GLOBAL_HULL`, `LOCAL_RADIAL`, `HSV_AI`, `FALLBACK_AI`
- suspicious badge when any option has suspicion notes

Required filters:

- All
- Marked
- Blank
- Needs Review
- Suspicious
- Global
- Local
- HSV/AI

These filters can be implemented with small vanilla JavaScript using embedded JSON. They must also degrade acceptably if JavaScript is disabled: all rows remain visible.

### 3. Main Decision Story Panel

When the user selects an option such as `Q6/f`, show one primary panel titled:

```text
Decision Story: Q6/f
```

It must include:

- final prediction: `MARKED`, `BLANK`, or `AMBIGUOUS`
- scoring method, for example `GLOBAL_HULL` or `LOCAL_RADIAL`
- score used by routing
- routing status and selected value
- a chronological stage list

Stage list format:

1. Global topology stage
2. Local radial stage
3. HSV/AI fallback stage
4. Score assignment
5. Routing constraints

For each stage, show:

- stage status: `ran`, `skipped`, `selected`, `rejected`, or `not_applicable`
- reason in plain language
- metrics used at that stage
- threshold comparison
- direct artifact links/images

Example wording for `Q6/f`:

```text
Global topology ran for Q6. The qualifying global hull selected a, b, c, d, e.
Option f was not selected because its option center was outside the qualifying hull.
Local radial then kept 99 ink pixels, activated 16/72 angle bins, and covered 80.0 degrees.
Because 80.0 <= BLANK_THRESHOLD_DEG 90, Q6/f was classified BLANK with score 0.0.
Routing kept it resolved because score 0.0 < low threshold 0.2.
```

Do not hardcode this exact `Q6/f` explanation. Generate it from the trace data.

### 4. Evidence Image Viewer

For each selected ROI, show a grid of evidence images:

- aligned ROI
- reference ROI
- diff mask
- radial mask
- HSV mask
- safe HSV mask
- core mask
- outer mask
- overlay decision

Requirements:

- Each image has a label and one-line metric caption.
- Images use stable dimensions and do not stretch incorrectly.
- Mask images should use nearest-neighbor rendering when zoomed.
- Clicking an image opens it larger in an in-page modal or a same-page zoom panel.
- The zoom view should include the file name and key dimensions.
- Keep original image files linked so a developer can open them directly.

Optional but preferred:

- Add a simple pixel-inspection mode using canvas for displayed images. On mouse move, show image-relative `x`, `y`, and RGB/gray value. This must work offline with local image files. If browser security prevents canvas pixel reads for `file://` in some browsers, keep the rest of the report functional and show a short in-report warning.

### 5. Pixel Accounting Panel

For each ROI, show a pixel accounting table:

| Metric | Value | Meaning |
| --- | ---: | --- |
| `diff_ink_pixels` | number | pixels different from reference before local removals |
| `diff_contour_count` | number | number of diff contours |
| `core_mask_pixels` | number | printed text/core region removed |
| `outer_mask_pixels` | number | outside-circle pixels removed |
| `radial_ink_pixels` | number | pixels kept for radial angle analysis |
| `radial_active_bin_count` | number | active angle bins after gap filling |
| `radial_degrees_covered` | number | active bins multiplied by 5 degrees |
| `hsv_ink_pixels` | number or blank | HSV safe-mask pixels if HSV/AI ran |
| `classifier_probability` | number or blank | classifier probability if AI ran |

Also show threshold rules next to the measurements:

- `BLANK_THRESHOLD_DEG = 90`
- `MARKED_THRESHOLD_DEG = 180`
- `NUM_BINS = 72`
- `DEGREES_PER_BIN = 5`
- `MIN_INK_PER_BIN = 2`
- `OUTER_RADIUS = 32`
- `CHECKBOX_INNER_MARGIN = 5`
- HSV L2 blank threshold: `< 20` safe-mask pixels
- HSV L2 marked threshold: `> 200` safe-mask pixels
- AI marked threshold: `> 0.85`
- AI blank threshold: `< 0.15`
- routing low threshold: `0.2`
- routing high threshold: `0.6`

Read these constants from the same imported module values used by the probe. Do not duplicate magic numbers inside the HTML renderer.

### 6. Radial Histogram Panel

For local radial analysis, show:

- angle histogram as a compact bar chart
- active bins highlighted
- blank threshold line at 90 degrees
- marked threshold line at 180 degrees
- measured degree total
- reason for blank/marked/ambiguous

The chart can be generated as:

- static SVG embedded in `index.html`, or
- PNG artifact per ROI, or
- simple HTML bars from `radial_histogram`

No external chart library.

### 7. Question-Level Global Topology Panel

Add a dedicated panel for each question where global topology applies.

This panel is essential. It must explain why an option was or was not selected by global topology.

For each question, generate and show:

- group crop coordinates
- option centers in group crop coordinates and page coordinates
- raw contour count
- valid contour count
- rejected contour count with reasons
- merge threshold used
- all clusters considered
- cluster hull area
- cluster total contour area
- solidity
- cluster bbox
- whether the cluster qualifies
- options whose centers are inside the cluster hull
- final `global_marked` option set

Artifacts per question:

```text
question_global/<question_id>/global_overlay.png
question_global/<question_id>/global_mask.png
question_global/<question_id>/cluster_overlay.png
question_global/<question_id>/global_trace.json
```

`global_overlay.png` must visually encode:

- option boxes
- option centers
- qualifying hulls
- non-qualifying hulls
- selected option centers
- rejected option centers
- text labels for option ids

Recommended visual convention:

- green hull: qualifies and can mark options
- yellow/orange hull: contour cluster exists but fails a threshold
- red option center: not selected
- green option center: selected
- cyan/magenta contours: raw and merged contour evidence

### 8. Routing Panel

For each question, show routing before and after constraints:

- original per-option score
- original selection state from thresholds
- min selections
- max selections
- number selected before constraints
- final selected value
- routing status
- review reason

This panel must make `needs_review` explainable. Example cases:

- ambiguous score between 0.2 and 0.6
- under-selection
- over-selection
- skipped routing due filtered `--question` or `--option` run

When routing is skipped because the run was filtered, explicitly show:

```text
Routing constraints were not evaluated because this probe was filtered. Run the whole page to inspect routing.
```

### 9. Suspicion Notes

Keep and expand `suspicion_notes`.

The report should surface suspicious traces in the navigator and in the selected ROI panel. Add notes when:

- diff mask has pixels but radial removed all or almost all
- radial degree is within 15 degrees of a decision threshold
- HSV safe-mask conflicts with diff mask
- AI classifier probability is near a threshold
- global topology marks an option but local radial would be blank
- local radial marks an option but global topology missed it
- option is near a global hull boundary
- contour cluster included the option center but failed solidity/area thresholds

The notes should name metrics, not just state "suspicious".

## Golden Explainability Scenario

Using the existing debug output from page 1, the improved report must be able to answer the `Q6/f` case from data alone.

Expected current behavior:

- `Q6/a` through `Q6/e` are `MARKED` by `GLOBAL_HULL`.
- `Q6/f` is `BLANK` by `LOCAL_RADIAL`.
- `Q6/f` has `score = 0.0`.
- `Q6/f` local radial keeps `99` pixels.
- `Q6/f` local radial activates `16/72` bins.
- `Q6/f` local radial covers `80.0` degrees.
- `Q6/f` is blank because `80.0 <= BLANK_THRESHOLD_DEG 90`.
- Global topology ran for `Q6`.
- The qualifying global hull selected `a`, `b`, `c`, `d`, `e`.
- `f` was not selected by that qualifying hull because its option center was outside the qualifying hull.

If the exact page image or profile changes later, the test should check the structural explanation rather than hardcoding every pixel number. For the current repository state, include this scenario as a regression/approval fixture if practical.
